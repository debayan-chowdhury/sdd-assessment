# INT Next.js Engineering Standards

You are assisting an engineering team at INT. Whenever you write, refactor,
or suggest code in this Next.js (App Router) project, you must strictly
adhere to the following rules:

## 1. Code Style and Structure
* Use TypeScript everywhere — no `.js`/`.jsx` files, no `any` unless a
  third-party type genuinely forces it (leave a reason if so).
* Build routes exclusively under `src/app/` using the App Router file
  conventions (`page.tsx`, `layout.tsx`, `route.ts`, `loading.tsx`,
  `error.tsx`). Do not introduce a `pages/` directory.
* Server Components are the default. Only add `'use client'` at the top of a
  file when the component genuinely needs interactivity, browser APIs, or
  React hooks like `useState`/`useEffect` — push the boundary as low in the
  tree as possible rather than marking whole route trees client-side.
* Prefer `async`/`await` for data fetching inside Server Components over
  `.then()/.catch()` chains.
* Keep components small and single-purpose; colocate a route's private
  components/hooks/utilities in a local folder (e.g. `_components/`) rather
  than one large file.
* Use descriptive, PascalCase names for components and camelCase for
  functions/variables. Avoid default exports for anything except route
  segment files (`page.tsx`, `layout.tsx`, etc.), where Next.js requires them.
* Style with Tailwind utility classes directly in JSX; avoid ad hoc inline
  `style={{}}` objects except for values that must be computed at runtime.

## 2. Error Handling
* Handle expected, recoverable errors (e.g. form validation failures, "not
  found" results) as return values or typed results, not thrown exceptions.
* Handle unexpected errors with route-level `error.tsx` boundaries and
  `global-error.tsx` at the root; never let a Server Component throw
  uncaught into a blank page.
* In Route Handlers (`route.ts`), wrap external calls in `try/catch`, log the
  error server-side with a structured logger (e.g. `pino`), and return a
  consistent JSON error shape: `{ error: { code: string, message: string } }`
  with the appropriate HTTP status — never leak stack traces or internal
  error details to the client.
* Never swallow a caught error silently; at minimum log it before returning
  or rethrowing.

## 3. Security
* Never hardcode secrets, API keys, or credentials. Read them from
  environment variables via `process.env`, and only expose a variable to the
  client by explicitly prefixing it `NEXT_PUBLIC_` — treat every
  non-prefixed env var as server-only and never pass it into a Client
  Component's props.
* Validate and parse all external input — form submissions, Route Handler
  request bodies, search params — with a schema library (e.g. Zod) before
  using it; do not trust `FormData` or `request.json()` shapes directly.
* Never use `dangerouslySetInnerHTML` with unsanitized input, and never call
  `eval()` or construct dynamic `Function()` bodies from user-controlled data.
* Set Server Actions and Route Handlers to validate auth/session state
  explicitly at the top of the function — do not assume middleware alone
  covers every entry point.

## 4. Performance
* Fetch data in Server Components / Route Handlers, not via client-side
  `useEffect` + `fetch` waterfalls; parallelize independent fetches with
  `Promise.all` rather than sequential `await`s.
* Use Next.js `<Image>` for all raster images and `next/font` for font
  loading instead of manual `<img>` tags or external `<link>` font imports.
* Apply `loading.tsx` / `<Suspense>` boundaries around slow data segments
  instead of blocking the whole route on one slow fetch.
* Avoid unnecessary `'use client'` boundaries and large client-side bundles;
  check that a new client dependency is actually needed before adding it.
* Cache and revalidate deliberately — set explicit `fetch` cache/`revalidate`
  options or `export const revalidate` rather than relying on defaults for
  data that changes.

## 5. Guardrails
* Never include comments indicating that code was generated by AI.
* Never write default commit messages that give hints of AI-generated code.
* Do not add any AI-specific configuration files (like `.cursorrules` or
  `.copilotignore`) outside of the `.agent/` directory.
